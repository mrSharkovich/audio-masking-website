# Совместимость Windows / Python

Проверка метаданных выполнена **8 ноября 2026 года** на основном компьютере. Python на нём: **3.11.9**, Windows. Целевые платформы вычислялись явно: обычный CPython **3.12 x64** и **3.13 x64**, Windows, GIL. Фактическая VM с Python 3.13.16 недоступна и не проверялась.

## Что удалось установить

| Профиль | Python 3.12 / Windows x64 | Python 3.13 / Windows x64 | Пакетов в обходе графа |
|---|---|---|---|
| Whisper small / faster-whisper | совместимые артефакты найдены | совместимые артефакты найдены | 27 |
| GigaAM-v3 CTC | совместимые артефакты найдены, ANTLR — sdist | совместимые артефакты найдены, ANTLR — sdist | 35 |
| GigaAM-Multilingual CTC 220M | совместимые артефакты найдены, ANTLR — sdist | совместимые артефакты найдены, ANTLR — sdist | 45 |

Полный список проверенных прямых и транзитивных пакетов, ограничения, версии и имена wheel-файлов: [compatibility/evidence.json](compatibility/evidence.json). Он получен чтением JSON API PyPI и Hugging Face. Архивы пакетов, код моделей и веса при этом аудите не скачивались. Открытый код GigaAM для проверки контракта отдельно читался с Hugging Face без сохранения исходников в комплекте и без выполнения.

Это результат **анализа метаданных**, а не успешной установки или распознавания. Упрощённый обход зависимостей не выполняет backtracking, не обрабатывает произвольные extras и не заменяет pip resolver. Используемые профили не запрашивают extras. Транзитивные версии впоследствии могут измениться: окончательную цепочку фиксируют отчёт установки и `pip freeze` на VM.

**Отдельное ограничение Hydra:** официальная [матрица Hydra 1.3](https://hydra.cc/docs/1.3/intro/) перечисляет Python 3.6–3.11. Поэтому наличие универсального wheel `hydra-core==1.3.2` не означает официальную поддержку 3.12/3.13. Оба профиля GigaAM на этих версиях Python остаются экспериментальными до проверки импортов и модели на VM. Новая Hydra 1.4 заявляет более новые Python, но пока является release candidate; она не подменяется автоматически в закреплённом стеке. При ошибке импорта не устанавливайте случайные версии: сохраните диагностику. Python 3.12 подготовлен как запасной путь, его успех также не гарантирован.

CPU-сборки torch/torchaudio устанавливаются отдельным шагом из официального CPU-индекса PyTorch. Наличие Windows wheels в PyPI само по себе не подтверждает доступность/импорт конкретного CPU-варианта на VM. Установщик останавливается при ошибке; не переходит автоматически к CUDA-сборке или компиляции нативных пакетов. `check-deps` дополнительно проверяет `torch.version.cuda is None`, простую CPU-операцию и доступность INT8 в CTranslate2.

Карточка GigaAM-v3 также рекомендует pyannote-audio 4.0.0 и TorchCodec 0.7.0 для полной инфраструктуры longform. Для TorchCodec 0.7.0 в PyPI есть Windows cp312/cp313 wheels, но это не доказывает совместимость всех DLL/версий FFmpeg. **В данном комплекте эти пакеты не используются и не устанавливаются**: короткие PCM-фрагменты до 20 секунд читаются через адаптер `prepare_wav`, без longform и VAD. Это существенно уменьшает цепочку зависимостей и исключает дополнительную модель сегментации.

Для обеих GigaAM исходный `transcribe()` имеет порог 25 секунд. В GigaAM-Multilingual результат может быть `TranscriptionResult.text`, а не строкой. Оба условия учтены в адаптерах. Исходный загрузчик вызывает `ffmpeg` с автоматическим числом потоков; здесь заменяется только ввод нормализованного PCM16, без изменения признаков и декодера.

## Какие модели доступны

Выбран официальный GigaAM-Multilingual **CTC 220M**, а не SSL encoder и не 600M Large. Карточка заявляет распознавание русского и английского; английское качество описано как умеренное. Наличие многоязычного pretraining само по себе не принималось за поддержку ASR на нужных языках.

В аудите закреплены следующие снимки (будущая команда `download` использует эти commit):

| gigaam-v3 | ai-sage/GigaAM-v3 / ctc | `15ef3b5a88da78f93134b3cb7f015c70aefa8946` |

## Что проверяется только на VM

1. Фактическая версия/архитектура Python и 20 настоящих WAV/TXT.
2. Полное разрешение и установка зависимостей, сборка чистого Python ANTLR.
3. CPU-пакеты torch, загрузка DLL и поддержка инструкций виртуального CPU.
4. Реальная конвертация частот/каналов через установленный PyAV.
5. Загрузка локальных снимков GigaAM/Whisper и их фактическое API.
6. RAM, watchdog и время реальных моделей, качество на датасете.

Если на 3.13 возникает проблема, предусмотрен отдельный путь 3.12: новый интерпретатор вручную рядом со старым, отдельные `.venvs/*-3.12`, те же требования и команды с `-PythonVersion 3.12`. Метаданные не выявили отсутствующих артефактов, но **не устанавливают совместимость во время исполнения**, в частности для Hydra 1.3. Переход на 3.12 — запасной вариант для проблем импорта/исполнения, не гарантированное исправление. Ничего автоматически не удаляется и системные настройки не меняются.
