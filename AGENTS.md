# AGENTS.md — AudioMask

## Назначение проекта

AudioMask — учебный веб-проект для локальной обработки и исследования маскирования аудиозаписей. Пользователь загружает аудио, прослушивает исходную и обработанную записи, получает результаты обработки, оценивает качество по PESQ/ViSQOL и при необходимости запускает распознавание речи.
Выполняй только запрошенную работу.

## Технологический стек и структура

- **Frontend:** React, TypeScript, Vite; каталог `frontend/`.
- **Backend:** Python и FastAPI — ориентир для серверной части; не создавай и не изменяй её без задачи пользователя.
- **Аудио:** WAV и, при реализации соответствующего функционала, FFmpeg для конвертации.
- **Метрики:** PESQ и ViSQOL; реальные значения можно показывать только после настоящего расчёта в допустимых условиях (в проекте — 16 кГц).
- **Локальное ASR:** для русского языка выбрана GigaAM-Multilingual, для английского — Whisper small multilingual. Язык аудио определяет модель; это не переключение языка интерфейса.
- Код интерфейса отделяй от API-адаптеров и логики обработки. Не вводи новые слои архитектуры без необходимости.

## Запуск, сборка и проверки

Команды выполняются в PowerShell из корня репозитория:

```powershell
cd frontend
npm.cmd run dev      # локальный сервер разработки
npm.cmd run build    # проверка TypeScript и production-сборка
npm.cmd run lint     # проверка линтером, если скрипт существует
npm.cmd run         # посмотреть доступные тестовые скрипты
```

После изменений запускай подходящие тесты из `frontend/package.json`, проверку типов, линтер и сборку, если они относятся к задаче. Не считай проверку успешной, если не запускал её. Для изменений документации достаточно проверить текст и затронутые файлы.

## Обязательные ограничения

1. **Закрытый алгоритм:** исходный код алгоритма маскирования находится вне репозитория. Не ищи, не читай, не копируй и не изменяй его. Интеграция допускается только через отдельно предоставленный пользователем контракт и адаптер. Не придумывай параметры вызова или способ демаскирования.
2. **Git и GitHub:** не выполняй Git-операции, не обращайся к GitHub, API, CLI или подключённым инструментам без прямого разрешения. Публикацией управляет пользователь.
3. **Сеть и установка:** не устанавливай зависимости, не скачивай модели, веса, исполняемые файлы и не используй платные сервисы без отдельного разрешения.
4. **Приватность:** не отправляй аудио, транскрипции, результаты обработки или секреты во внешние сервисы; не включай их в репозиторий, тестовые фикстуры и логи без явной необходимости и разрешения.
5. **Достоверность:** отличай реальные интеграции от заглушек. Не выдавай имитацию маскирования, распознавания или метрик за рабочую реализацию; явно обозначай недоступность неподключённых функций.
6. **Границы продукта:** не добавляй самостоятельно авторизацию, платёжные функции, историю, дополнительные метрики или AI-возможности. WER/CER могут использоваться в отдельном исследовании моделей, но не добавляются на сайт без запроса.
7. **Сохранность:** не удаляй и не перезаписывай пользовательские файлы, записи, результаты или существующие изменения без разрешения. Не задавай произвольные сроки хранения аудио.
8. **Интерфейс:** сохраняй согласованный дизайн, адаптивность, светлую и тёмную темы. Не проводи незапрошенный редизайн или рефакторинг.
9. **Безопасность обработки:** проверяй содержимое загруженных файлов; не передавай пользовательские пути и параметры в shell через конкатенацию команд. Не раскрывай внутренние пути и исключения в UI.
10. **Исследования:** экспериментальные скрипты и результаты ASR держи отдельно от кода приложения, если пользователь не поручил интеграцию.
