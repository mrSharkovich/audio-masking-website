# AudioMask — локальный ASR API

Python 3.11+, FastAPI. Frontend подключён к ASR API через локальный Vite proxy.
Реализованы процессные адаптеры Whisper и GigaAM и отдельные worker-скрипты.
Без настроенных окружений и локальных весов API возвращает HTTP 503.
Разработка и локальные проверки выполняются на основном ПК без настоящих моделей;
перенос на VM выполняется позднее, после завершения разработки.
В проект не входят модели, веса, пользовательские записи и результаты экспериментов.

## Установка и запуск на Windows

Из корня проекта в PowerShell. Команды установки приведены для выполнения
после отдельного разрешения на зависимости; агент их не выполнял.

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Сервер слушает только loopback. Проверка из другого окна:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
curl.exe -X POST http://127.0.0.1:8000/api/asr/transcribe -F "language=ru" -F "file=@sample.wav"
```

`sample.wav` — собственный локальный WAV допустимого формата. До подключения
моделей второй запрос вернёт 503. Swagger: `http://127.0.0.1:8000/docs`.
Не включены CORS, публичное размещение и сетевой доступ с других компьютеров.

Для совместного запуска откройте второе окно PowerShell из корня проекта:

```powershell
cd frontend
npm.cmd run dev
```

Браузер обращается к `/api/*` на origin Vite, proxy пересылает запросы на
`http://127.0.0.1:8000`. CORS для этого сценария не требуется. Если порт backend
недоступен, запустите его, например, с `--port 18000`, а перед Vite задайте
`$env:AUDIOMASK_BACKEND_URL = "http://127.0.0.1:18000"`. Проверка через proxy:
`Invoke-RestMethod http://127.0.0.1:5173/api/health` (порт Vite берите из терминала).
Без настроенных моделей транскрибация корректного WAV должна вернуть 503 и сообщение
о недоступности в UI, без тестового текста. Подробности — [frontend README](../frontend/README.md).
Отмена браузерного fetch прекращает ожидание клиентом; серверный worker может работать
до завершения/тайм-аута. Эндпоинт серверной отмены пока не предусмотрен.

## API

- `GET /api/health` → `200 {"status":"ok"}`. Проверяет сервер, а не готовность моделей.
- `POST /api/asr/transcribe`: multipart с единственными полями `file` (один файл)
  и `language` (`ru` или `en`). Повторные/лишние поля, в том числе `model`, отклоняются.

Сервер выбирает модель: `ru` → `gigaam-multi` (GigaAM-Multilingual CTC 220M),
`en` → `whisper` (Whisper small multilingual; целевой runtime faster-whisper CPU INT8).
Идентификатор, присланный клиентом, никогда не управляет выбором модели.

Успешный ответ реального либо явно внедрённого тестового адаптера:

```json
{"language":"en","model":"whisper","text":"..."}
```

Пустой текст от адаптера сохраняется пустым. Выдуманный текст API не создаёт.
Ошибка имеет вид `{"error":{"code":"asr_unavailable","message":"..."}}`.
Коды HTTP: 413 — размер; 415 — неподдерживаемое/повреждённое аудио;
422 — поля или язык, пустой файл; 503 — модель не подключена/недоступна;
502 — сбой адаптера/некорректный ответ; 504 — тайм-аут worker;
503 с кодом `asr_busy` — лимит параллельных запросов;
503 с кодом `audio_preparation_unavailable` — нет библиотек преобразования;
500 — внутренняя ошибка запроса.
Ответы не содержат исключений, имён загруженных файлов и серверных путей.

## Загрузки и временные файлы

Поддерживается **RIFF WAV, integer PCM 8/16/24/32 бит, mono/stereo, 8–192 кГц**.
Float WAV, WAVE_FORMAT_EXTENSIBLE, MP3, FLAC и OGG пока не поддерживаются.
Подготовка ASR выполняется в отдельный WAV 16 кГц, mono, PCM16: равновесное
усреднение каналов, полифазный ресемплинг `scipy.signal.resample_poly`, округление
и ограничение диапазона PCM16. Исходный файл не изменяется. Для уже готового
WAV лишняя копия не создаётся. VAD, обрезка и нормализация громкости не выполняются.
Конвертация использует NumPy/SciPy, а не FFmpeg: эти библиотеки уже доступны
на основном ПК и проверены синтетическим сигналом. Новые пакеты агент не устанавливал.
Расширение и MIME не доказывают корректность и не используются для выбора декодера:
проверяются RIFF/WAVE, границы чанков, параметры PCM, число и полнота отсчётов.

По умолчанию файл ограничен 25 МиБ и 300 секундами. Всё multipart-тело ограничено
размером файла + 64 КиБ для полей/заголовков; лимит действует и без Content-Length.
Тело запроса буферизуется в памяти в пределах этого лимита, затем разбирается.
Это не streaming ASR. Суммарная память зависит от числа параллельных запросов;
рекомендуется ограничить конкурентность Uvicorn по результатам измерений.
Лимит файла действует до преобразования: 48 кГц stereo PCM16 занимает больше места,
чем нормализованный WAV; 25 МиБ допускают примерно 136 секунд такой записи.

Для запроса создаётся отдельный временный каталог со сгенерированным именем.
Имя из загрузки не используется в пути. WAV удаляется при выходе из обработки,
включая ошибки адаптера/валидации. Multipart-файлы закрываются контекстным менеджером.
Синхронный адаптер работает в thread pool; его завершения дожидаются до удаления
аудио. Адаптер не должен оставлять фоновые процессы, читающие файл после возврата.
При аварийном завершении процесса ОС или выключении VM гарантировать очистку
невозможно; постоянное хранение записей и политика удаления результатов не вводятся.
Приложение не пишет аудио/транскрипции в логи и не содержит внешних сетевых вызовов.

## Запуск workers и ограничения

Один запрос запускает один worker отдельным Python-процессом. Backend не импортирует
Torch, Transformers и faster-whisper. Команда формируется списком аргументов,
`shell=False`, с фиксированным серверным скриптом и изолированным `python -I`.
Пользователь не может выбирать worker или передавать путь к окружению.

Общий для ru/en лимит по умолчанию — один запрос, включая подготовку WAV.
Очереди нет: занятый сервер отвечает `503/asr_busy`. Лимит действует в пределах
одного процесса backend: запускайте Uvicorn с одним worker (`--workers 1`).
Несколько процессов backend потребуют отдельного межпроцессного ограничителя.

Тайм-аут процесса по умолчанию 120 секунд, включая старт/загрузку модели.
Время загрузки на VM может потребовать увеличения. NumPy/SciPy-подготовка WAV
не входит в этот тайм-аут; она ограничена размером/длительностью входа.
На Windows используется Job Object с kill-on-close: дерево процессов завершается
при ошибке, тайм-ауте и нормальном выходе. Worker ждёт входного JSON до загрузки
библиотек, чтобы родитель успел включить Job Object. Если Job Object недоступен,
запрос завершается ошибкой, запуска без ограничения дерева нет. Окна консоли
не открываются. На POSIX используется отдельная process group с SIGKILL;
эта ветвь на основном Windows-ПК не проверялась.

stdin — один JSON `{audio, weights, language}` с абсолютными локальными путями;
stdout — UTF-8 JSON `{"text":"..."}`. Exit 0 — успех, 3 — отсутствуют ресурсы,
2 — ошибка модели/протокола. stdout и stderr читаются ограниченно (по 256 КиБ
на поток); превышение завершает процесс. stderr не сохраняется и не попадает
в API. Ожидание завершения дерева предшествует очистке WAV.

## Конфигурация

Переменные окружения считываются при создании приложения. `.env.example` — справочник,
автоматического чтения `.env` нет. Пример задания лимита:

```powershell
$env:AUDIOMASK_MAX_FILE_BYTES = "26214400"
$env:AUDIOMASK_MAX_DURATION_SECONDS = "300"
```

| Переменная | Назначение |
| --- | --- |
| `AUDIOMASK_MAX_FILE_BYTES` | Положительный лимит размера файла |
| `AUDIOMASK_MAX_DURATION_SECONDS` | Положительный лимит длительности |
| `AUDIOMASK_TEMP_DIRECTORY` | Необязательный существующий доступный для записи каталог; иначе системный temp |
| `AUDIOMASK_GIGAAM_PYTHON` | Python окружения GigaAM на VM |
| `AUDIOMASK_GIGAAM_WEIGHTS` | Локальные веса GigaAM на VM |
| `AUDIOMASK_WHISPER_PYTHON` | Python окружения faster-whisper на VM |
| `AUDIOMASK_WHISPER_WEIGHTS` | Локальные веса Whisper small multilingual на VM |
| `AUDIOMASK_WORKER_TIMEOUT_SECONDS` | Тайм-аут дочернего процесса, 120 по умолчанию |
| `AUDIOMASK_MAX_CONCURRENT_ASR` | Общий лимит на процесс backend, 1 по умолчанию |
| `AUDIOMASK_MAX_WORKER_OUTPUT_BYTES` | Лимит каждого потока worker, 262144 по умолчанию |
| `AUDIOMASK_CPU_THREADS` | Число потоков CPU библиотек worker, 4 по умолчанию |

Пути к Python и весам должны быть абсолютными. Пустые/несуществующие пути означают
недоступность ASR. Наличие пути не подтверждает готовность модели: это устанавливается
при запуске worker. Не задавайте модельные окружения на основном ПК для локальных
тестов: тесты явно внедряют свои адаптеры и подставной worker.

## Тестирование

После разрешения на тестовые зависимости:

```powershell
cd backend # если вы ещё в корне проекта
.\.venv\Scripts\python.exe -m pip install -r requirements-test.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m compileall -q app workers tests
```

Тесты используют unittest, FastAPI TestClient/HTTPX внутри процесса, синтетический
WAV и подставные subprocess-workers. Проверяются 48 кГц stereo → 16 кГц mono PCM16,
сохранность оригинала/частоты тона, PCM-разрядности, маршрутизация, тайм-ауты,
ограничение ru/en, ошибки/вывод workers, очистка и завершение дочернего процесса
Windows Job Object. Вызовы библиотек моделей проверяются через подставные модули.
Серверный порт, сеть, настоящие модели и датасет не нужны. Эти проверки не доказывают
совместимость конкретных весов и установленного на VM ASR-окружения.
HTTPX 0.28.1 совместим с проверенной конфигурацией; Starlette 1.2.1 выводит
предупреждение о будущей замене HTTPX на httpx2. Зависимости автоматически не меняются.

## Окружения и проверка при окончательном переносе на VM

1. После завершения локальной разработки указать пути к двум установленным
   окружениям Python и полным локальным каталогам весов.
2. Whisper worker ожидает **CTranslate2 small multilingual**, а не исходные PyTorch
   веса. Нужны `model.bin`, `config.json`, `tokenizer.json`, `preprocessor_config.json`.
   Используется `faster_whisper.WhisperModel(local_path, device="cpu", compute_type="int8",
   local_files_only=True)`, язык фиксирован `en`, перевод и VAD выключены. Проверяется
   multilingual; соответствие каталога размеру small — ответственность конфигурации.
3. GigaAM worker ожидает полный **Transformers snapshot GigaAM-Multilingual CTC 220M**
   с config, весами, `modeling_gigaam.py` и локальными зависимостями custom code.
   Проверяется вложенная конфигурация `multilingual_ctc`, encoder 16×768.
   Вызов: `AutoModel.from_pretrained(local_path, local_files_only=True,
   trust_remote_code=True)`, CPU, eval, inference_mode, затем `model.transcribe(path)`.
   `trust_remote_code` здесь разрешает только заранее размещённый доверенный локальный
   код модели. Если VM использует отдельный пакет gigaam/иной формат checkpoint,
   нужно адаптировать worker к этому формату до интеграционного теста.
4. Оба worker включают `HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE`, отключают телеметрию
   и Python socket connections. Имя Hugging Face-модели нигде не передаётся загрузчику.
   При неполном локальном snapshot запрос завершается ошибкой, скачивания не должно
   быть. Python-ограничение сети не заменяет изоляцию ОС для произвольного native/custom
   кода: при финальной проверке подтвердить отсутствие исходящего трафика.
5. Проверить совместимость версий Torch/torchaudio/Transformers и faster-whisper/CT2,
   фактические ru/en транскрипции, длинные записи, память и время старта на 4 vCPU,
   10 ГБ RAM, отказоустойчивость и отсутствие сети при отключённом интернете.
   Каждая модель загружается заново на запрос: постоянных resident workers пока нет.
6. Проверить сквозной frontend-сценарий с настоящими моделями. HTTP-адаптер уже отправляет
   один фактический файл и язык за запрос; model возвращается сервером и проверяется
   клиентом. Для both выполняются последовательные запросы, чтобы не нарушать общий
   лимит ASR. Маскированная запись станет доступна только после отдельного подключения
   маскирования; отсутствие результата не подменяется исходником/демонстрацией.

Контракты загрузчиков сверены с первичными описаниями:
[GigaAM-Multilingual](https://huggingface.co/ai-sage/GigaAM-Multilingual),
[конфигурация CTC](https://huggingface.co/ai-sage/GigaAM-Multilingual/blob/main/config.json),
[faster-whisper](https://pypi.org/project/faster-whisper/).
Модельные зависимости не добавляются в окружение API и не устанавливались агентом.
