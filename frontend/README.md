# AudioMask frontend

Первая реализация интерфейса по change `design-audiomask-homepage`: React + TypeScript + Vite. Backend, закрытый алгоритм, реальные PESQ/ViSQOL и LLM не подключены. Публикацию выполняет только пользователь.

## Текущее состояние и запуск

Исходники и конфигурация подготовлены. Зависимости **не установлены**; установка требует отдельного разрешения пользователя. Lock-файл намеренно не создан без установки. Не запускайте обходные команды установки через Harness.

После разрешённой установки зависимостей из `frontend/package.json`:

```powershell
cd frontend
npm.cmd run dev
```

Vite слушает только `127.0.0.1`. Адрес будет указан в терминале. Для проверки локальной production-сборки доступны `npm.cmd run build` и `npm.cmd run preview`; исходный TSX нельзя открыть напрямую как готовый сайт.

Команды проверок после установки:

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run build
```

Отдельная проверка только тестовых адаптеров доступна без npm-пакетов на Node.js 24 с поддержкой встроенного чтения TypeScript:

```powershell
node --test tests/adapters.native.test.mjs
```

Она не проверяет React, CSS, браузер, типизацию или реальные аудиоинтеграции.

При подготовке frontend эта команда реально выполнена: **3 теста PASS, 0 FAIL** (отдельный синтетический WAV, ошибки/недоступность и частичный ответ метрик, выбор источников транскрибации). Это не результат запуска Vitest.

## Возможности интерфейса

- Одна русскоязычная страница Audio Studio: шапка с якорями, рабочая область, три шага, «О проекте» и footer.
- Светлая/тёмная тема следует `prefers-color-scheme` до первого ручного переключения. Ручной выбор действует до перезагрузки; localStorage, sessionStorage, cookies и сервер для темы не используются.
- Выбор одного файла и drag-and-drop, реальное имя/размер, длительность из браузерных метаданных и нативное предпрослушивание. Пустой файл и выбор нескольких файлов показывают ошибку. Поддержка форматов/лимиты не заявляются до согласования backend; расширение или MIME не считаются доказательством пригодности файла.
- На время демонстрационного запроса выбор/удаление/замена/drop и повторный запуск заблокированы в UI и обработчиках. После успеха или ошибки блокировка снимается. Отмены нет.
- Результат заменяет форму, содержит два нативных аудиоплеера без аудиоволн. Возврат к форме и «Открыть текущий результат» не запускают обработку повторно. Новая запись сбрасывает прошлый результат; история и восстановление после перезагрузки отсутствуют.
- Метрики и необязательная транскрибация запускаются отдельными кнопками; у текста выбирается источник, есть копирование с обработкой отказа буфера обмена.

## Демонстрация и безопасность данных

Постоянно показано «Демонстрация — реальные операции не выполняются». В свёрнутом блоке «Демонстрационные сценарии» можно выбрать успех, ошибку или недоступность; для дополнительных операций — частичный результат и пустой текст. Ожидание — задержка ответа тестового адаптера для проверки UI, не имитация работы алгоритма. Процент выполнения отсутствует.

В успешном сценарии создаётся отдельный односекундный синтетический WAV-тон. Он не использует содержимое выбранного файла и не является маскированием. Второй плеер и скачивание явно помечены демонстрационными, имя файла — `audiomask-demo-tone-not-masked.wav`. Кнопка «Скачать обработанное аудио» недоступна: настоящего результата нет. Нельзя считать этот тон преобразованным исходником. Параметры WAV относятся только к искусственной тестовой фикстуре, не определяют требования будущего алгоритма.

PESQ/ViSQOL показывают заранее заданные **демонстрационные** значения, не вычисленные оценки. Текст явно обозначен примером, не распознаванием. При выключенном демонстрационном режиме реальная обработка недоступна; скрытого fallback нет.

Выбранное аудио остаётся в памяти открытой страницы, не отправляется и не сохраняется. Object URL освобождаются после смены записи/результата и размонтирования. Адаптеры не выполняют сетевых запросов и не используют алгоритм, метрики или модель. Серверное хранение не реализовано, срок хранения не назначен.

## Структура

- `src/components/` — форма, плееры, результат, дополнительные панели и демонстрационные сценарии.
- `src/hooks/` — тема, object URL, рабочий процесс и защита асинхронных ответов.
- `src/types/audio.ts` — концептуальные типы границы адаптеров; это не контракт реального API.
- `src/adapters/demoAudio.ts` — изолированные тестовые ответы и генератор синтетической фикстуры.
- `src/styles.css` — токены тем, Audio Studio, адаптивные правила, focus/reduced-motion.
- `src/**/*.test.*`, `src/test/` — Vitest/Testing Library: тема, отсутствие хранения, состояния, блокировка файла, плееры, дополнительные действия и object URL.
- `tests/adapters.native.test.mjs` — отдельные Node-тесты адаптеров без внешних пакетов.

## Проверки и оставшиеся ограничения

Vitest/компонентные тесты, typecheck, ESLint и production build: **SKIPPED**, необходимые локальные пакеты пока отсутствуют. Браузерная приёмка на 360×800 и 1440×900, клавиатура, контраст, масштаб 200% и реальное декодирование аудио: **SKIPPED** до запуска приложения. Наличие CSS и тестовых файлов не доказывает прохождение этих проверок.

Целевые браузеры: Chrome, Edge и Firefox на ПК; Chrome на Android; Safari на iPhone. Фактическое поведение нативных плееров, медиаформатов, clipboard и `prefers-color-scheme` нужно проверить в них после установки. Дополнительные панели сбрасывают своё представление при возврате к форме; повторное открытие результата не запускает их автоматически.

Автоматические Hooks могут выдавать статические `REVIEW` и `SKIPPED`; это не заменяет тесты. Фактически выполненные проверки и ход реализации фиксируются координатором в OpenSpec change.

Следующий этап требует отдельной спецификации: реальные API/DTO, форматы и лимиты, WAV/конвертация, хранение и удаление, публичный контракт алгоритма, сравниваемая пара и условия метрик, согласованная локальная LLM. Исходники закрытого алгоритма не нужны и не читаются. Регистрация, история, WER/CER и отчёты AI не добавлены.
