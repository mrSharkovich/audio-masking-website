# AudioMask frontend

React + TypeScript + Vite. Транскрибация подключена к локальному FastAPI через HTTP.
Маскирование, демаскирование, PESQ и ViSQOL пока недоступны. Демонстрационные
сценарии на странице не показаны, фиктивные результаты не используются как ASR.

## Локальный запуск Windows

Команды рассчитаны на уже установленные зависимости. Установка новых зависимостей
требует отдельного разрешения. Модели и веса на основном компьютере не нужны.

Первое окно PowerShell, из корня проекта:

```powershell
cd backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Если backend имеет отдельное venv, используйте его `Scripts\python.exe`.
Не задавайте пути к модельным окружениям на основном ПК: без них корректный WAV
получит `503/asr_unavailable`, а не транскрипцию. Подробнее: [backend README](../backend/README.md).

Второе окно PowerShell, из корня проекта:

```powershell
cd frontend
npm.cmd run dev
```

Откройте показанный Vite адрес, страница `/process`. Vite dev и preview пересылают
`/api/*` в `http://127.0.0.1:8000`; браузер отправляет запрос на свой origin,
CORS не требуется. Адрес задаётся в `vite.config.ts` и переопределяется переменной
окружения либо записью в локальном `frontend/.env.local`:

```powershell
$env:AUDIOMASK_BACKEND_URL = "http://127.0.0.1:18000"
npm.cmd run dev -- --port 15173 --strictPort
```

Для этого примера backend должен слушать `--port 18000`. После изменения настройки
перезапустите Vite. Используйте только локальный доверенный backend: proxy передаёт
ему аудио. IP VM и пользовательские пути в конфигурации не зафиксированы.

`npm.cmd run build` создаёт `dist/`, `npm.cmd run preview` проверяет сборку локально.
В production Vite proxy отсутствует: нужен same-origin reverse proxy для `/api/*`
и SPA fallback на `index.html` для четырёх маршрутов сайта.

## Проверка связи без настоящих моделей

```powershell
Invoke-RestMethod http://127.0.0.1:5173/api/health
```

Используйте фактический порт Vite. Ожидается `status: ok`; это не готовность моделей.
На `/process` выберите WAV, язык и исходное аудио, нажмите «Запустить транскрибацию».
Без моделей появится сообщение о недоступности локальной ASR-модели. В DevTools
Network: `POST /api/asr/transcribe`, multipart-поля только `file` и `language`.
При остановленном backend показывается понятная ошибка связи/получения результата.

```powershell
curl.exe -X POST http://127.0.0.1:5173/api/asr/transcribe -F "language=ru" -F "file=@sample.wav"
```

Здесь `sample.wav` — собственный локальный WAV. Не используйте приватные записи для
логов или фикстур. Для автоматических проверок используются синтетические
данные из памяти, подставные HTTP-ответы и backend-адаптеры.

## ASR-контракт и ограничения

- HTTP-адаптер: `src/adapters/httpTranscription.ts`; только POST с `file` и `language`.
- Ответ сервера: `{language, model, text}`. Проверяются язык, известная модель и строка
  текста. Клиент не отправляет `model`; сервер выбирает `ru → gigaam-multi`,
  `en → whisper`. Пустой ответ обозначается как завершение без текста.
- Ошибки `{error:{code,message}}`: обрабатываются 400/413/415/422, недоступность модели
  и занятость 503, сбой 502, серверный тайм-аут 504 и остальные HTTP-ошибки.
  Произвольные серверные сообщения и исключения в UI не выводятся.
- Поддерживается только RIFF WAV integer PCM 8/16/24/32 бит, mono/stereo, 8–192 кГц.
  Backend создаёт 16 кГц mono PCM16, не меняя оригинал. Frontend проверяет RIFF/WAVE
  по первым байтам, сервер проверяет полное содержимое и параметры. Переименование
  MP3 в `.wav` не делает файл пригодным. Float WAV и WAVE_FORMAT_EXTENSIBLE не поддерживаются.
- Общий выбор файла позволяет выбирать любые форматы для браузерного предпрослушивания,
  но ASR не обещает MP3/FLAC/OGG. Непустой файл не гарантирует поддержку браузером
  или backend. По умолчанию backend допускает 25 МиБ и 300 секунд; при 48 кГц stereo
  PCM16 лимит размера соответствует примерно 136 секундам. Лимиты настраиваются сервером.
- Источник — original/masked/both. Для masked нужен фактический Blob результата,
  помеченный `demonstration: false`. Исходник и синтетический тон никогда его не заменяют.
  Пока маскирование не подключено, masked недоступен; при both распознаётся оригинал
  и отдельно показывается недоступность маскированной записи. Для двух настоящих
  файлов выполняются два последовательных HTTP-запроса.
- Повторный запуск заблокирован до завершения. «Отменить запрос» прерывает fetch;
  уход со страницы, замена/удаление файла и смена параметров отменяют запрос и
  сбрасывают старый ответ. Поздние ответы игнорируются. Клиент ждёт до 180 секунд
  на один HTTP-запрос, backend по умолчанию ограничивает worker 120 секундами.
- Отмена fetch не гарантирует немедленную остановку уже начатого серверного worker:
  он завершится либо достигнет серверного тайм-аута; в это время backend может вернуть
  `asr_busy`. Отдельного API серверной отмены нет.
- Аудио передаётся локальному backend только по явному запуску транскрибации.
  Постоянное хранение, история, localStorage транскрипций и внешние ASR-сервисы не добавлены.

## Навигация, темы и проверки

Сохранены `/`, `/process`, `/how-it-works`, `/about`, история браузера, две темы и
нативное предпрослушивание. Выбор языка живёт в памяти App и сохраняется между страницами;
файл и результаты страницы сбрасываются при уходе с неё. После перезагрузки язык ru.
Структура и CSS не перерабатывались.

```powershell
cd frontend
npm.cmd run test
npm.cmd run test:adapters
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run build
```

Vitest/Testing Library проверяют интерфейс, HTTP-контракт, ошибки без фиктивного текста,
выбор языка/источника, последовательность запросов, отмену, поздние ответы и навигацию.
Node-тесты `tests/adapters.native.test.mjs` проверяют только прежние демонстрационные
адаптеры и не подтверждают распознавание. Они не включены в Vitest.

Без моделей нельзя подтвердить качество и скорость настоящего распознавания,
совместимость локальных весов и полноценную обработку реального маскированного файла.
