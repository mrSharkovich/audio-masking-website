# Выполненные проверки

Основной компьютер, 8 ноября 2026 года, Windows, Python 3.11.9. Это **не VM** с Python 3.13.16.

- Синтаксис `run_benchmark.ps1`: Windows PowerShell Parser, ошибок нет.
- Синтаксис 12 Python-модулей: `ast.parse`, ошибок нет; `__pycache__` не создавался.
- `python -B test_local.py`: **18 проверок, OK**. Проверены 20 синтетических пар, параметры WAV, отсутствующие/лишние файлы, повреждённый/пустой/усечённый WAV, некорректный UTF-8, BOM, пустой эталон, примеры WER, сохранность оригинала при копировании, полное покрытие фрагментами, взвешенный WER отчёта и отсутствие итогового WER при ошибке, запрет загрузки без явного флага, коды CLI, строковый/объектный контракт результата GigaAM на заглушке. Watchdog остановил реальный тестовый процесс ожидания по времени и по имитации превышения RAM; реальные модели не запускались.
- Исправленный `run_benchmark.ps1 -Action check-data` действительно запущен через Windows PowerShell с явным путём к Python 3.11.9 и синтетическому датасету: `Valid pairs: 20/20`, код 0. Это проверка ветки валидации, не модельного окружения.
- Аудит JSON-метаданных: все шесть профилей (три модели × Python 3.12/3.13) завершились со статусом `metadata-compatible`; подробности в `compatibility/evidence.json` и `COMPATIBILITY.md`.
- Локальный `git status --short` исходного проекта: пустой; проект не изменён.

Синтетические артефакты находятся в `.checks/` внутри комплекта. Их нельзя принимать за результаты настоящего ASR-эксперимента. При переносе можно скопировать всю папку: реальные результаты создаются отдельно в `results/`.

Не выполнялись: установка зависимостей, создание модельных окружений, загрузка весов, реальные ASR-прогоны, реальная конвертация через PyAV, проверка на целевой VM. Удалённый компьютер недоступен. Поведение лимитов RAM/времени с настоящими моделями и работоспособность нативных DLL остаются для проверки на VM.
