# Agent Harness проекта

Agent Harness задаёт правила работы Codex над сайтом маскирования аудиозаписей: ограничивает область задачи, разделяет ответственность, подключает проверки и сохраняет результаты. Основной источник правил — [AGENTS.md](../../AGENTS.md), подтверждённых результатов — [журнал проверок](verification.md).

## Запуск

В терминале PowerShell выполните:

```powershell
codex-local
```

Установленный локальный `codex-local.cmd` переходит в каталог проекта и запускает Codex CLI с `--no-daemon`. Он привязан к локальным путям проекта и установленного расширения; после их изменения обёртку потребуется актуализировать.

Для защищённых операций используйте CLI через `codex-local`. По журналу от 29.10.2026 Dependency Guard блокировал `python -m pip install --help` в CLI, но пропустил её в боковом чате Codex в VS Code; сообщений PostToolUse там также не получено. Причина различия неизвестна. Наличие конфигурации не подтверждает работу Hooks в расширении.

## Установлено и настроено

| Компонент | Назначение и расположение |

| Skills | `.agents/skills/`: `audio-processing` — аудио и метрики; `frontend-design` — интерфейс; `vercel-react-best-practices` — React; `web-design-guidelines` — UX и доступность; `playwright` — браузерные проверки; `caveman` — краткий стиль. |
| OpenSpec Skills | `openspec-propose`, `openspec-explore`, `openspec-update-change`, `openspec-apply-change`, `openspec-sync-specs`, `openspec-archive-change` — подготовка и ведение изменений. |
| Hooks | `.codex/hooks.json` и `.codex/hooks/`: Security Check, Dependency Guard, Agent Role Check, Session Summary, Test Runner, Code Quality, QA, Spec Compliance, Secrets & Privacy и Documentation Check. |

## Проверено

По [журналу](verification.md), без новых тестов при подготовке этой инструкции:

- Session Summary создал `records.json` на Stop и `summary.json` на SessionEnd.
- В CLI Dependency Guard и Security Check заблокировали зафиксированные проверочные команды до выполнения.
- Создан и завершён QA-субагент; зарегистрированы SubagentStart и SubagentStop.
- На временном Python-файле Code Quality подтвердил синтаксис; QA и Secrets & Privacy вернули `REVIEW`.
- После исправления Secrets & Privacy Check проверены 74 вымышленных пути по правилам Git и Hook; публичные `.env.example` разрешены. Первая проверка завершилась ошибкой, повторная прошла; итоговая — без предупреждений. В CLI подтверждены `Trusted` и включённое состояние `[x]` этой проверки.

## Не подтверждено или проверено частично

- Автоматическое применение TOML-профилей к субагентам не подтверждено.
- Hooks в расширении VS Code не подтверждены; результаты CLI нельзя переносить на расширение.
- В записанной проверке Test Runner и Spec Compliance вернули `SKIPPED`, Documentation Check — `UNKNOWN`. Это не означает успешную проверку приложения.
- Наличие команды OpenSpec подтверждено, выполнение её рабочего сценария не проверено этим аудитом.
- Для Playwright MCP не подтверждены запуск браузера и сценарии; для Context7 — успешные запросы документации. Все MCP нельзя считать полностью работающими.
- Проверка `.gitignore` не доказывает защиту уже отслеживаемых Git файлов; отсутствие предупреждений Hook не является гарантией безопасности.

## Использование ролей

По явному поручению пользователя основной Codex распределяет задачи и проверяет совместимость результатов:

- `frontend` — React/TypeScript, интерфейс, API-клиент, адаптивность и доступность.
- `backend` — FastAPI, аудио/FFmpeg, API и адаптеры алгоритма, метрик и локальной транскрибации.
- `qa` — ревью и проверки; по умолчанию без изменения файлов и самостоятельного исправления основного кода.

Для каждой роли явно задавайте задачу, разрешённые файлы, ограничения и ожидаемые проверки. Передавайте применимые инструкции из соответствующего TOML-профиля в поручении, не полагаясь на его автоматическую загрузку. Профили не разрешают расширять задачу или делегировать её дальше. Главный Codex собирает результаты и сообщает итог пользователю.

## Порядок будущей работы

1. **OpenSpec:** исследовать задачу и подготовить необходимые артефакты в пределах поручения.
2. **Согласование задачи:** определить объём, поведение продукта и решения пользователя; перед существенными изменениями предложить краткий план.
3. **Реализация:** выполнять согласованную задачу небольшими связанными изменениями, применять нужные Skills и роли.
4. **Проверки:** запускать подходящие тесты, типизацию, линтер и сборку по мере их появления; отдельно отмечать заглушки и реальные интеграции. Сообщения Hooks не заменяют проверки поведения.
5. **Документирование:** фиксировать выполненные проверки, результаты, ошибки и ограничения; обновлять журнал Harness при его диагностике.

## Безопасность

- Codex запрещено взаимодействовать с GitHub, включая API, MCP, CLI, `push`, `pull` и `fetch`. Публикацию выполняет только пользователь; локальные `git status` и `git diff` разрешены.
- Codex запрещено искать, читать, запрашивать, копировать или изменять исходники закрытого алгоритма. Подключение возможно только через предоставленный контракт и отдельный адаптер; недоступность алгоритма показывается явно.
- Пользовательское аудио не отправляется внешним сервисам; транскрибация предусматривается локально. Модель LLM, платные операции, срок хранения и существенные преобразования аудио требуют согласования.
- Секреты, пользовательские аудиозаписи и результаты обработки не включаются в Git. Важные файлы не удаляются без явного разрешения. Harness не заменяет соблюдение этих правил.

Наличие Harness не разрешает создавать исходный код сайта без отдельного поручения пользователя.
