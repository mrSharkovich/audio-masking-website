# Оценка качества аудио

На странице `/process` отметьте от одной до трёх пар и нажмите «Оценить
качество». По умолчанию отмечена пара «Исходная ↔ Маскированная». Запрос
передаёт локальному backend записи из текущего результата, необходимые для
выбранных пар. Для каждой пары отдельно рассчитываются PESQ Wideband и два
варианта ViSQOL Speech при 16 кГц. Ошибка или недоступность одной метрики
сохраняет результаты остальных вычислений.

Для проверки без внешнего исполнителя включите [локальную заглушку маскирования](../README.md#локальный-тестовый-режим-маскирования).
Её результаты содержат копии подготовленной записи. Оценки этих пар описывают
звучание копий. Стойкость маскирования требует отдельного исследования.

## Окружение метрик на Windows

Вручную подготовьте отдельное 64-битное Python-окружение, например Python 3.11.
Нативные модули должны соответствовать версии и архитектуре Python.

- **PESQ Wideband.** Установите пакет `pesq==0.0.4` в окружение метрик.
  При сборке пакета из исходников на Windows потребуются инструменты сборки
  C++ MSVC и Windows SDK. Адаптер вызывает `pesq(16000, reference, degraded, "wb")`
  и принимает только конечный MOS-LQO в пределах 1–4,65.
- **ViSQOL Speech.** Установите `visqol-python==3.8.0`. Для обоих режимов
  установите `visqol-python[lattice]==3.8.0` с совместимым `ai-edge-litert`.
  Worker создаёт `VisqolApi` с `mode="speech"` и передаёт
  `use_lattice_model=False` или `True`. `measure(reference_path, degraded_path)`
  возвращает объект `SimilarityResult`. Числовой MOS-LQO берётся из
  `result.moslqo` (диапазон 1–5). Для lattice используется модель пакета.
  Если LiteRT недоступен или библиотека сообщает о переходе на полиномиальный
  режим, вариант с lattice помечается как недоступный. [Документация пакета](https://pypi.org/project/visqol-python/3.8.0/)

Перед запуском FastAPI задайте абсолютные пути в PowerShell, подставив свои:

```powershell
$env:AUDIOMASK_QUALITY_PYTHON = 'C:\path\metrics\Scripts\python.exe'
$env:AUDIOMASK_QUALITY_TIMEOUT_SECONDS = '30'
```

После перезапуска проверьте `GET /api/quality/status`. Статус `available`
означает, что worker загрузил зависимости и, для ViSQOL, инициализировал
модель. Для проверки самого расчёта используйте локальную речевую запись
длиной несколько секунд и запустите оценку через интерфейс. Настройка метрик
опциональна для запуска FastAPI, сайта и ASR.

## API и правила сравнения

- `GET /api/quality/status` возвращает объект `metrics` с ключами `PESQ`,
  `ViSQOL` и `ViSQOL_LATTICE`. Каждая проверка даёт `available`,
  `unavailable` или `error`.
- `POST /api/quality/evaluate` принимает multipart с повторяемым текстовым
  полем `pairs`. Передавайте от одного до трёх разных ключей из таблицы и
  по одному файлу на каждую запись, входящую в выбранные пары.
  Ответ `comparisons` содержит только запрошенные пары. В каждой есть
  `PESQ`, `ViSQOL` (без lattice) и `ViSQOL_LATTICE` (с lattice).
  Успех имеет вид `{"status":"success","value":4.1}`. Недоступность и ошибки
  отдельных метрик содержат `status` и `message`. Ошибки запроса возвращаются
  со структурой `error.code` и `error.message`.
- Исходник проходит ту же подготовку, что и при маскировании. Обе обработанные
  записи должны быть непустыми WAV mono PCM16 при 16 кГц. Размер исходника
  и длительность каждой записи ограничены настройками загрузки приложения.
  Предел каждого результата маскирования учитывает размер WAV после подготовки.
- Если подготовленный исходник короче маскированной или демаскированной
  записи, в конец его временной копии добавляются нулевые отсчёты до длины
  обработанной записи. Например, для 60640 и 65536 отсчётов добавляются 4896
  нулей. Для каждой пары копия готовится независимо из одного и того же
  исходника. Все три метрики пары используют эту копию в формате WAV mono
  PCM16 при 16 кГц. При равной длине дополнение не выполняется. Если
  обработанная запись короче исходной, пара получает ошибку несовпадения
  длительности. Для пары «Маскированная ↔ Демаскированная» по-прежнему требуется
  равное число отсчётов. Пользовательские файлы и результаты маскирования
  остаются без изменений.
- Минимум проверяется по количеству отсчётов до дополнения. Для PESQ
  требуется 4000 отсчётов (0,25 с), для ViSQOL — 16000 (1 с). Проверка на
  постоянный сигнал, включая цифровую тишину, также учитывает только
  отсчёты самой записи. Для осмысленной оценки используйте записи речи.
  Библиотеки могут отклонить сигнал и при соблюдении этих условий.
- Бюджет загрузки и подготовки общий. Каждое вычисление или проба получает
  собственный тайм-аут, по умолчанию 30 секунд. Один запрос оценки или пробы
  может выполняться одновременно в процессе API. При отключении клиента
  сервер завершает дочерний процесс. Временные WAV, включая дополненные копии,
  удаляются при завершении запроса, в том числе после ошибки, тайм-аута или отмены.

Порядок аргументов закреплён в API и при расчёте не меняется.

| Значение `pairs` | Reference | Degraded |
| --- | --- | --- |
| `masked` | Исходная (`original`) | Маскированная (`masked`) |
| `demasked` | Исходная (`original`) | Демаскированная (`demasked`) |
| `masked_demasked` | Маскированная (`masked`) | Демаскированная (`demasked`) |

PESQ и ViSQOL оценивают воспринимаемое качество. Даже максимальная оценка
сама по себе не доказывает совпадение отсчётов.
