# AudioMask — локальный ASR API

Оценка PESQ и ViSQOL отрабатывает отдельными локальными процессами. Инструкции
по окружению Windows, API и условиям расчёта приведены в [руководстве по оценке качества](docs/audio-quality.md).

Python 3.11+, FastAPI. Frontend подключён к ASR API через локальный Vite proxy.
Реализованы процессные адаптеры Whisper и GigaAM и отдельные worker-скрипты.
Без настроенных окружений и локальных весов API возвращает HTTP 503.
На основном Windows-ПК вручную подтверждено распознавание английской речи через
Whisper small и русской речи через GigaAM-Multilingual CTC 220M через FastAPI и frontend.
Обе модели работают в отдельных Python-окружениях вне репозитория.
В проект не входят модели, веса, пользовательские записи и результаты экспериментов.

## Установка и запуск на Windows

Из корня проекта в PowerShell. Команды установки приведены для выполнения
после отдельного разрешения на зависимости; агент их не выполнял.

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Сервер слушает только loopback. Проверка из другого окна:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
curl.exe -X POST http://127.0.0.1:8000/api/asr/transcribe -F "language=ru" -F "file=@sample.wav"
```

`sample.wav` — собственный локальный WAV допустимого формата. До подключения
моделей второй запрос вернёт 503. Swagger: `http://127.0.0.1:8000/docs`.
Не включены CORS, публичное размещение и сетевой доступ с других компьютеров.

Для совместного запуска откройте второе окно PowerShell из корня проекта:

```powershell
cd frontend
npm.cmd run dev
```

Браузер обращается к `/api/*` на origin Vite, proxy пересылает запросы на
`http://127.0.0.1:8000`. CORS для этого сценария не требуется. Если порт backend
недоступен, запустите его, например, с `--port 18000`, а перед Vite задайте
`$env:AUDIOMASK_BACKEND_URL = "http://127.0.0.1:18000"`. Проверка через proxy:
`Invoke-RestMethod http://127.0.0.1:5173/api/health` (порт Vite берите из терминала).
Без настроенных моделей транскрибация корректного WAV должна вернуть 503 и сообщение
о недоступности в UI, без тестового текста. Подробности — [frontend README](../frontend/README.md).
Отмена браузерного fetch прекращает ожидание клиентом; серверный worker может работать
до завершения/тайм-аута. Эндпоинт серверной отмены пока не предусмотрен.

## API

- `GET /api/health` → `200 {"status":"ok"}`. Проверяет сервер, а не готовность моделей.
- `POST /api/asr/transcribe`: multipart с единственными полями `file` (один файл)
  и `language` (`ru` или `en`). Повторные/лишние поля, в том числе `model`, отклоняются.

Сервер выбирает модель: `ru` → `gigaam-multi` (GigaAM-Multilingual CTC 220M),
`en` → `whisper` (Whisper small multilingual; целевой runtime faster-whisper CPU INT8).
Идентификатор, присланный клиентом, никогда не управляет выбором модели.

Успешный ответ реального либо явно внедрённого тестового адаптера:

```json
{"language":"en","model":"whisper","text":"..."}
```

Пустой текст от адаптера сохраняется пустым. Выдуманный текст API не создаёт.
Ошибка имеет вид `{"error":{"code":"asr_unavailable","message":"..."}}`.
Коды HTTP: 413 — размер; 415 — неподдерживаемое/повреждённое аудио;
422 — поля или язык, пустой файл; 503 — модель не подключена/недоступна;
502 — сбой адаптера/некорректный ответ; 504 — тайм-аут подготовки или распознавания;
503 с кодом `asr_busy` — лимит параллельных запросов;
503 с кодом `audio_preparation_unavailable` — недоступна подготовка аудио;
503 с кодом `ffmpeg_unavailable` — не задан/недоступен конкретный FFmpeg для GigaAM;
500 — внутренняя ошибка запроса.
Ответы не содержат исключений, имён загруженных файлов и серверных путей.

## Загрузки и временные файлы

Для ASR поддерживается **RIFF WAV, integer PCM 8/16/24/32 бит, mono/stereo, 8–192 кГц**.
При настроенном FFmpeg доступны те же форматы, что и для маскирования
и оценки качества, включая MP3, M4A, FLAC, OGG, AAC, AIFF, AMR, AC-3,
E-AC-3, AU и аудиодорожки Matroska/WebM. FFmpeg принимает только локальный
временный файл и разрешённые демультиплексоры. Расширение и MIME не определяют
декодер. Перед передачей модели проверяется WAV 16 кГц, mono, PCM16.
Для поддерживаемого PCM WAV сохранена существующая подготовка NumPy/SciPy.
Уже подготовленный WAV используется напрямую. Исходный файл не изменяется.
Разрыв соединения прерывает декодирование и очищает частичный WAV. Если
модель уже начала распознавание, временный WAV удаляется после завершения
или тайм-аута модели.

По умолчанию файл ограничен 25 МиБ и 300 секундами. Всё multipart-тело ограничено
размером файла + 64 КиБ для полей/заголовков; лимит действует и без Content-Length.
Тело запроса буферизуется в памяти в пределах этого лимита, затем разбирается.
Это не streaming ASR. Суммарная память зависит от числа параллельных запросов;
рекомендуется ограничить конкурентность Uvicorn по результатам измерений.
Лимит файла действует до преобразования: 48 кГц stereo PCM16 занимает больше места,
чем нормализованный WAV; 25 МиБ допускают примерно 136 секунд такой записи.

Для запроса создаётся отдельный временный каталог со сгенерированным именем.
Имя из загрузки не используется в пути. WAV удаляется при выходе из обработки,
включая ошибки адаптера/валидации. Multipart-файлы закрываются контекстным менеджером.
Синхронный адаптер работает в thread pool; его завершения дожидаются до удаления
аудио. Адаптер не должен оставлять фоновые процессы, читающие файл после возврата.
При аварийном завершении процесса ОС или выключении VM гарантировать очистку
невозможно; постоянное хранение записей и политика удаления результатов не вводятся.
Приложение не пишет аудио/транскрипции в логи и не содержит внешних сетевых вызовов.

## Запуск workers и ограничения

Один запрос запускает один worker отдельным Python-процессом. Backend не импортирует
Torch, Transformers и faster-whisper. Команда формируется списком аргументов,
`shell=False`, с фиксированным серверным скриптом и изолированным `python -I`.
Пользователь не может выбирать worker или передавать путь к окружению.

Общий для ru/en лимит по умолчанию — один запрос, включая подготовку WAV.
Очереди нет: занятый сервер отвечает `503/asr_busy`. Лимит действует в пределах
одного процесса backend: запускайте Uvicorn с одним worker (`--workers 1`).
Несколько процессов backend потребуют отдельного межпроцессного ограничителя.

Тайм-аут процесса по умолчанию 120 секунд, включая старт/загрузку модели.
Время загрузки на VM может потребовать увеличения. NumPy/SciPy-подготовка WAV
не входит в этот тайм-аут; она ограничена размером/длительностью входа.
На Windows используется Job Object с kill-on-close: дерево процессов завершается
при ошибке, тайм-ауте и нормальном выходе. Worker ждёт входного JSON до загрузки
библиотек, чтобы родитель успел включить Job Object. Если Job Object недоступен,
запрос завершается ошибкой, запуска без ограничения дерева нет. Окна консоли
не открываются. На POSIX используется отдельная process group с SIGKILL;
эта ветвь на основном Windows-ПК не проверялась.

stdin — один JSON `{audio, weights, language}` с абсолютными локальными путями;
stdout — UTF-8 JSON `{"text":"..."}`. Exit 0 — успех, 3 — отсутствуют ресурсы,
4 — недоступен FFmpeg, 2 — ошибка модели/протокола. stdout и stderr читаются ограниченно (по 256 КиБ
на поток); превышение завершает процесс. stderr не сохраняется и не попадает
в API. Ожидание завершения дерева предшествует очистке WAV.

## Конфигурация

Переменные окружения считываются при создании приложения. `.env.example` — справочник,
автоматического чтения `.env` нет. Пример задания лимита:

```powershell
$env:AUDIOMASK_MAX_FILE_BYTES = "26214400"
$env:AUDIOMASK_MAX_DURATION_SECONDS = "300"
```

| Переменная | Назначение |
| --- | --- |
| `AUDIOMASK_MAX_FILE_BYTES` | Положительный лимит размера файла |
| `AUDIOMASK_MAX_DURATION_SECONDS` | Положительный лимит длительности |
| `AUDIOMASK_TEMP_DIRECTORY` | Необязательный существующий доступный для записи каталог; иначе системный temp |
| `AUDIOMASK_GIGAAM_PYTHON` | Python отдельного окружения GigaAM |
| `AUDIOMASK_GIGAAM_WEIGHTS` | Локальные веса GigaAM |
| `AUDIOMASK_WHISPER_PYTHON` | Python отдельного окружения faster-whisper |
| `AUDIOMASK_WHISPER_WEIGHTS` | Локальные веса Whisper small multilingual |
| `AUDIOMASK_FFMPEG_PATH` | Абсолютный путь к `ffmpeg.exe` для GigaAM и декодирования форматов маскирования, выходящих за пределы встроенной поддержки PCM WAV |
| `AUDIOMASK_WORKER_TIMEOUT_SECONDS` | Тайм-аут дочернего процесса, 120 по умолчанию |
| `AUDIOMASK_MAX_CONCURRENT_ASR` | Общий лимит на процесс backend, 1 по умолчанию |
| `AUDIOMASK_MAX_WORKER_OUTPUT_BYTES` | Лимит каждого потока worker, 262144 по умолчанию |
| `AUDIOMASK_CPU_THREADS` | Число потоков CPU библиотек worker, 4 по умолчанию |

Пути к Python и весам должны быть абсолютными. Пустые/несуществующие пути означают
недоступность ASR. Наличие пути не подтверждает готовность модели: это устанавливается
при запуске worker. Автоматические тесты используют свои адаптеры и подставной worker.

## Локальный тестовый режим маскирования

Режим по умолчанию выключен. Для ручной проверки задайте обе переменные
в PowerShell перед запуском backend и оставьте оба сервера на loopback.
Используйте уже настроенное окружение API. Например, из корня репозитория:

```powershell
$env:AUDIOMASK_ENV = 'development'
$env:AUDIOMASK_MASKING_STUB = '1'
Set-Location .\backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 18080
```

Во втором PowerShell, из корня репозитория:

```powershell
$env:AUDIOMASK_BACKEND_URL = 'http://127.0.0.1:18080'
Set-Location .\frontend
npm.cmd run dev
```

Откройте `http://127.0.0.1:5173/process`, выберите аудиофайл и запустите тестовую
обработку. Для отключения задайте `$env:AUDIOMASK_MASKING_STUB = '0'` перед
перезапуском backend и обновите страницу. Тестовый режим также недоступен
без `AUDIOMASK_ENV=development` и для запросов с адресов вне loopback.

- `GET /api/masking/status` возвращает `available`, `test_mode` и `notice` для интерфейса.
- `POST /api/masking/process` принимает multipart с одним полем `file`.
  Необязательные поля `mode` (`one-sided` или `two-sided`) и `matrix`
  (4, 8, 16, 32, 64, 128, 256, 512) по умолчанию равны `two-sided` и `64`.
  Применяются существующие ограничения размера и длительности. Обычный PCM WAV
  готовится встроенным способом. При настроенном `AUDIOMASK_FFMPEG_PATH` backend
  также принимает декодируемые WAV, MP3, M4A, FLAC, OGG, AAC, AIFF, AMR, AC-3,
  E-AC-3, AU и аудиодорожки Matroska/WebM. Доступные кодеки зависят от сборки FFmpeg.
  Формат определяется по содержимому. Backend использует первую аудиодорожку,
  проверяет выходной WAV 16 кГц mono PCM16 и сохраняет байты оригинала.
  Повреждённый или неподдерживаемый файл отклоняется с 415, недоступный
  преобразователь возвращает 503. Списки воспроизведения и сетевые входы
  исключены. API транскрибации сохраняет свои требования к PCM WAV.
- Успешный JSON содержит `test_mode: true`, `masking_performed: false`,
  `notice`, `mode`, `selected_matrix`, `applied_matrix` и два объекта WAV
  `masked` и `demasked`. В каждом есть `file_name`, `media_type: "audio/wav"`
  и `base64`. Это независимые копии подготовленного WAV 16 кГц mono PCM16.
  Уменьшение размера матрицы имитируется по числу отсчётов.
- При ошибке API возвращает `error.code` и `error.message` без аудио.
  Отключённый режим возвращает 503, истечение бюджета времени возвращает 504.
  `AUDIOMASK_MASKING_TIMEOUT_SECONDS` по умолчанию равен 30 секундам.
  Тайм-аут и отключение клиента проверяются между этапами. Текущая синхронная
  операция заканчивается перед очисткой. Временные файлы удаляются в рамках
  запроса. Браузер воспроизводит полученные копии из памяти.

### Подключение внешнего исполнителя

Укажите абсолютные пути к доверенному Python-интерпретатору и скрипту-обёртке в
`AUDIOMASK_MASKING_RUNNER_PYTHON` и `AUDIOMASK_MASKING_RUNNER_SCRIPT`. Выключите
заглушку через `AUDIOMASK_MASKING_STUB=0` и перезапустите backend. Для заглушки
оставьте оба пути пустыми. Неполная конфигурация и конфликт режимов приводят к
`503/masking_unavailable`. Заданное время включает загрузку, преобразование,
выполнение и проверку файлов. Лимит составляет одну обработку на процесс API.

Backend запускает один процесс Python без shell в каталоге обёртки. Процесс
получает через stdin один JSON-объект UTF-8 и затем EOF:

```json
{"protocol_version":1,"input_path":"<prepared WAV>","masked_output_path":"<masked WAV>","demasked_output_path":"<demasked WAV>","mode":"two-sided","matrix_size":64}
```

Все пути абсолютные. Обёртка должна прочитать запрос, создать два непустых WAV
16 кГц mono PCM16 по указанным путям и напечатать в stdout ровно один JSON:

```json
{"protocol_version":1,"status":"ok","applied_matrix_size":64}
```

Размер в ответе должен быть одним из восьми допустимых размеров матрицы. При
ошибке обёртка завершает работу с ненулевым кодом. Служебный вывод допускается
только в stderr. Backend ограничивает оба потока 64 КиБ каждый и не передаёт их
пользователю. При тайм-ауте и отключении клиента backend завершает дерево
процессов перед удалением временной папки. Обёртка запускается как доверенный
локальный код с правами backend.

Реальный результат возвращается через тот же `POST /api/masking/process` с
`test_mode: false`, `masking_performed: true`, `notice: null` и файлами
`masked.wav` и `demasked.wav` внутри прежних полей ответа. Проверить подключение
можно прямым запросом к API. Текущий frontend включает обработку только
для тестового режима.

## Тестирование

После разрешения на тестовые зависимости:

```powershell
cd backend # если вы ещё в корне проекта
.\.venv\Scripts\python.exe -m pip install -r requirements-test.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m compileall -q app workers tests
```

Тесты используют unittest, FastAPI TestClient/HTTPX внутри процесса, синтетический
WAV и подставные subprocess-workers. Проверяются 48 кГц stereo → 16 кГц mono PCM16,
сохранность оригинала/частоты тона, PCM-разрядности, маршрутизация, тайм-ауты,
ограничение ru/en, ошибки и вывод workers, изоляция PATH для FFmpeg, очистка и
завершение дочерних процессов через Windows Job Object. Вызовы библиотек моделей
проверяются через подставные модули. Серверный порт, сеть, модели и датасет не нужны.
HTTPX 0.28.1 совместим с проверенной конфигурацией; Starlette 1.2.1 выводит
предупреждение о будущей замене HTTPX на httpx2. Зависимости автоматически не меняются.

## Окружения ASR на Windows

1. Указать абсолютные пути к интерпретаторам двух отдельных Python-окружений
   и полным локальным каталогам весов.
2. Whisper worker ожидает **CTranslate2 small multilingual**, а не исходные PyTorch
   веса. Нужны `model.bin`, `config.json`, `tokenizer.json`, `vocabulary.txt`.
   Для faster-whisper 1.2.1 `preprocessor_config.json` необязателен: без него
   используются штатные настройки feature extractor. Создавать или отдельно
   загружать такой файл для Systran small не требуется.
   Используется `faster_whisper.WhisperModel(local_path, device="cpu", compute_type="int8",
   local_files_only=True)`, язык фиксирован `en`, перевод и VAD выключены. Проверяется
   multilingual; соответствие каталога размеру small — ответственность конфигурации.
3. GigaAM worker ожидает полный **Transformers snapshot GigaAM-Multilingual CTC 220M**
   с `config.json`, `pytorch_model.bin`, `modeling_gigaam.py` и локальными зависимостями custom code.
   В рабочем окружении проверены PyTorch `2.8.0+cpu`, TorchAudio `2.8.0+cpu`
   и `pyannote.audio` `3.4.0`.
   Проверяются вложенная конфигурация `multilingual_ctc`, encoder 16×768 и локальные
   auto_map, без ссылок на другой Hub repository. Для этого CTC snapshot отдельный
   tokenizer.model не нужен: словарь находится в config.
   Вызов: `AutoModel.from_pretrained(local_path, local_files_only=True,
   trust_remote_code=True)`, явные CPU/torch.float32, eval, inference_mode, затем
   `model.transcribe(path).text` с проверкой строкового типа.
   Указать `AUDIOMASK_FFMPEG_PATH` до запроса: custom code вызывает FFmpeg даже для
   нормализованного WAV. Backend добавляет каталог настроенного файла в начало
   `PATH` только дочернего процесса GigaAM, чтобы вспомогательные вызовы находили
   `ffmpeg.exe` по имени. Worker привязывает вызов через `run` в модуле модели к
   полному настроенному пути с отключённым shell и протоколами file/pipe.
   `trust_remote_code` здесь разрешает только заранее размещённый доверенный локальный
   код модели.
4. Оба worker включают `HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE`, отключают телеметрию
   и Python socket connections/DNS. Имя Hugging Face-модели нигде не передаётся загрузчику.
   При неполном локальном snapshot запрос завершается ошибкой, скачивания не должно
   быть. Python-ограничение сети не заменяет изоляцию ОС для произвольного native/custom
   кода.
5. Каждая модель загружается заново на запрос. HTTP-адаптер отправляет один файл
   и язык за запрос. Сервер возвращает поле `model`, которое проверяет клиент.
   Для режима both запросы выполняются последовательно в рамках общего лимита ASR.

Контракты загрузчиков сверены с первичными описаниями:
[GigaAM-Multilingual](https://huggingface.co/ai-sage/GigaAM-Multilingual),
[конфигурация CTC](https://huggingface.co/ai-sage/GigaAM-Multilingual/blob/main/config.json),
[faster-whisper](https://pypi.org/project/faster-whisper/).
Модельные зависимости не добавляются в окружение API и не устанавливались агентом.

Предварительные команды и варианты зависимостей описаны в
[плане локальной установки](docs/local-asr-install-plan.md).
